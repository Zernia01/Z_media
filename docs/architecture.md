# ZM 0.1.0 구조

- `core`: UTF-8 파일 입출력, 손상된 설정값의 기본값 복구, 설정 저장.
- `media`: FFmpeg demux/codec, seek/flush, 스트림 변경. 작업 스레드가 소유하며 UI에서 직접 접근하지 않습니다.
- `player`: 명령 전달, 상태 스냅샷, 오디오 기준 clock, 프레임 소유권/큐.
- `video`: D3D11VA 선택, 소프트웨어 대체. SDL 텍스처 업로드/출력은 UI 스레드에서 수행합니다.
- `subtitle`: libavfilter/libass 자막 합성, 파일 자동 검색. 그래프는 디코딩 스레드가 소유합니다.
- `playlist`: 제한된 파일 목록과 순서/반복/무작위 선택.
- `input`: 단축키 매칭, 변경, 충돌 검사와 복원.
- `i18n`: 실행 파일 옆의 UTF-8 INI 리소스.
- `ui`: 창과 컨트롤, 영상 출력, 설정/재생목록. 텍스트 텍스처는 제한된 캐시에 보관합니다.
- `platform`: Windows Unicode 파일 선택 창과 설치된 시스템 글꼴 선택.

현재 demux와 영상/오디오 디코딩은 하나의 작업 스레드에서 수행합니다. 이후 독립 packet queue와 전용 decode thread로 분리할 수 있게 UI/상태 API를 분리했습니다. 영상 큐는 최대 12개이면서 약 64 MiB의 프레임 예산에 맞게 수를 줄이며, 매우 큰 단일 프레임은 1개까지 허용합니다. 오디오 큐는 약 0.5초입니다. FFmpeg 자체 버퍼/디코더 메모리는 별도입니다.

Seek와 파일 변경 요청은 atomic flag로 대기 중인 큐 생산을 중단합니다. Worker가 decoder/queue를 정리하고 generation을 갱신하면 UI가 이전 텍스처를 폐기합니다. 프레임은 queue로 전달할 때 소유권이 이동하며, 소비하거나 큐를 비울 때 해제합니다.

GPU 디코딩 후 현재는 CPU로 프레임을 전송해 YUV420P 텍스처를 업로드합니다. Zero-copy, HDR/10-bit 출력, 색 관리와 tone mapping은 후속 단계입니다. 자막은 영상 프레임에 합성되므로 자막 옵션 변경 시 현재 위치를 다시 탐색해 이미 합성된 큐를 비웁니다.

내장 텍스트 자막을 libass 그래프로 로드할 때는 FFmpeg가 해당 파일의 자막을 미리 읽습니다. 큰 파일/느린 디스크에서 초기 지연과 메모리 사용이 늘어날 수 있으며, 이 그래프 초기화 구간은 일반 demux의 interrupt callback과 별개입니다. 향후 스트리밍 libass 연동으로 교체해야 합니다.
