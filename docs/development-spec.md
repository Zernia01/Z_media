# Zernia media (ZM) 개발 작업지시서

- 정식 이름: Zernia media
- 약칭: ZM
- 버전: 0.1.0

# C 기반 고성능 영상 미디어 플레이어 개발 작업지시서

## 1. 프로젝트 목표

C 언어를 중심으로 고성능 데스크톱 영상 미디어 플레이어를 개발한다.

프로그램의 핵심 목표는 다음과 같다.

- 빠른 실행 속도
- 낮은 CPU/RAM 사용량
- GPU 하드웨어 디코딩
- 현대적이고 깔끔한 UI
- 다크/라이트 모드
- 최대한 많은 영상/음성/자막 형식 지원
- Unicode 완전 지원
- 다국어 UI
- 사용자 지정 단축키
- 세밀한 자막 설정
- 대용량/고해상도 영상에서도 안정적인 재생
- 모듈화된 구조
- 향후 기능 확장이 쉬운 구조

코덱을 직접 구현하지 말고 FFmpeg/libav 계열 라이브러리를 사용한다.

플레이어의 UI, 상태 관리, 설정, 재생 제어, 렌더링 연결 등의 핵심 프로그램 구조는 C를 중심으로 작성한다.

---

# 2. 기본 개발 환경

우선 Windows 11 x64를 주 플랫폼으로 개발한다.

가능하면 이후 Linux로 포팅할 수 있도록 Windows 전용 코드와 플랫폼 독립 코드를 분리한다.

빌드 시스템:

- CMake
- x64
- Debug / Release 구성 분리

프로젝트 전체가 가능한 한 최신 안정 버전의 라이브러리를 사용할 수 있도록 한다.

Release 빌드는 성능 최적화를 적용한다.

---

# 3. 미디어 엔진

FFmpeg 계열 라이브러리를 사용한다.

주요 구성:

- libavformat
- libavcodec
- libavutil
- libswscale
- libswresample
- 필요시 libavfilter

FFmpeg 실행 파일을 단순히 외부 프로세스로 실행하는 구조가 아니라 가능하면 라이브러리를 직접 연동한다.

다음 파이프라인을 명확하게 분리한다.

파일 입력
→ Demux
→ Video/Audio/Subtitle Packet
→ Decode
→ Video Rendering / Audio Output / Subtitle Rendering
→ A/V Synchronization

각 구성요소는 모듈화한다.

# 7. GPU 하드웨어 가속

가능하면 자동으로 GPU를 감지한다.

지원 가능한 환경에서는 다음 하드웨어 디코딩 기술을 사용한다.

- NVIDIA NVDEC
- Intel Quick Sync Video
- AMD 계열 하드웨어 가속
- Windows D3D11VA
- DXVA2

설정에 다음 옵션을 만든다.

하드웨어 가속:

- 자동
- 사용
- 사용 안 함

가능하면 세부 디코더 선택도 제공한다.

하드웨어 디코딩에 실패하면 프로그램이 종료되지 않고 자동으로 소프트웨어 디코딩으로 fallback한다.

가능하면 Zero-Copy 또는 이에 가까운 GPU 렌더링 구조를 고려한다.

현대적인 미디어 플레이어 형태의 깔끔하고 단순한 UI를 만든다.

메인 화면에는 최소한 다음을 배치한다.

- 영상 화면
- 재생/일시정지
- 이전/다음
- 탐색 바
- 현재 시간
- 전체 영상 시간
- 볼륨
- 음소거
- 자막
- 오디오 트랙
- 재생 속도
- 설정
- 전체화면

영상 위에서 마우스가 일정 시간 움직이지 않으면 컨트롤 UI를 자동으로 숨긴다.

마우스를 다시 움직이면 표시한다.

# 14. 설정 → 자막 ON/OFF

설정에 별도의 `자막` 페이지를 만든다.

최상단에:

자막 사용

ON / OFF

옵션을 제공한다.

OFF 상태에서는 외부/내장 자막을 렌더링하지 않는다.

영상마다 자막을 켜고 끄는 기능도 플레이어 컨트롤에서 제공한다.

기본 설정 항목:

- 자막 사용 ON/OFF
- 자동 자막 검색 ON/OFF
- 내장 자막 자동 선택
- 선호 자막 언어
- 자막 글꼴
- 글자 크기
- 글자 굵기
- 글자 색상
- 외곽선
- 외곽선 두께
- 그림자
- 배경
- 화면상 자막 위치
- 수직 위치 조절
- 자막 동기화

자막 동기화는 밀리초 단위로 조절 가능하게 한다.

예:

-500 ms
0 ms
+500 ms

# 20. 사용자 지정 단축키

사용자가 각 기능의 단축키를 직접 지정할 수 있게 한다.

설정 → 단축키 화면:

기능 | 현재 단축키 | 변경

형태로 표시한다.

검색창도 제공한다.

예:

검색: "자막"

결과:

자막 ON/OFF
다음 자막
이전 자막
자막 지연 증가
자막 지연 감소

단축키 변경 버튼을 누르면:

"새 단축키를 입력하세요."

상태로 전환하고 사용자의 키 입력을 캡처한다.

다음과 같은 조합을 지원한다.

- Ctrl
- Alt
- Shift
- Win 사용 여부는 플랫폼 정책에 맞게 판단
- 문자 키
- 숫자
- Function Key
- 방향키
- 기타 적절한 키

예:

Ctrl + Shift + S

# 35. 스레드 구조

UI 스레드에서 영상 디코딩을 직접 수행하지 않는다.

예:

UI Thread
Demux Thread
Video Decode Thread
Audio Decode Thread
Subtitle Processing
Audio Output
Rendering

형태로 역할을 적절하게 분리한다.

Queue에 최대 크기를 두어 장시간 재생 시 RAM 사용량이 계속 증가하지 않게 한다.

Thread 종료와 재생 파일 변경 시 race condition, deadlock, use-after-free가 발생하지 않도록 주의한다.

---

# 36. A/V Sync

영상과 오디오의 동기화를 중요하게 구현한다.

장시간 영상을 재생해도 음성과 영상이 점점 어긋나지 않아야 한다.

Seek 이후에도 동기화를 빠르게 복구한다.

일반적으로 오디오 clock을 기준으로 적절한 A/V synchronization 방식을 구현하되, FFmpeg timestamp/time_base를 정확하게 처리한다.

---

# 37. Seek 최적화

긴 영상에서도 탐색이 지나치게 느리지 않게 한다.

Seek 시:

- 기존 packet queue 정리
- decoder flush
- timestamp 재설정
- 필요한 위치부터 decode

등을 안전하게 처리한다.

사용자가 탐색바를 빠르게 연속으로 움직이는 상황도 고려한다.

---

# 38. 메모리 관리

C 프로그램이므로 메모리 안정성을 매우 중요하게 다룬다.

모든 allocation/free의 소유권을 명확하게 한다.

특히 다음을 검사한다.

- Memory Leak
- Double Free
- Use After Free
- Buffer Overflow
- NULL Pointer
- Thread Race

파일을 수백 번 연속으로 열고 닫아도 메모리가 계속 증가하지 않아야 한다.

---

# 39. 오류 처리

지원하지 않거나 손상된 파일을 열었을 때 프로그램이 종료되면 안 된다.

사용자에게 이해하기 쉬운 오류를 표시한다.

예:

"미디어 파일을 열 수 없습니다."

필요하면 상세 정보에서 FFmpeg 오류를 확인할 수 있게 한다.

---

# 45. 자동 업데이트 구조

# 50. Codex 작업 방식

각 Phase를 완료한 후 다음 단계로 넘어간다.

기존 기능을 삭제하거나 임시 구현으로 덮어쓰지 않는다.

코드를 변경할 때 기존 모듈과 API를 먼저 확인한다.

빌드 오류가 발생한 상태로 작업 완료라고 판단하지 않는다.

각 단계마다:

1. 코드 작성
2. CMake 구성 확인
3. 컴파일
4. compiler warning 확인
5. 오류 수정
6. 실행 가능한지 확인
7. 기존 기능 regression 확인

순서로 진행한다.

README.md에 다음 내용을 지속적으로 기록한다.

- 필요한 라이브러리
- 빌드 방법
- 실행 방법
- 프로젝트 구조
- 현재 구현된 기능
- 아직 구현되지 않은 기능
- 알려진 문제

최종적으로 단순한 FFmpeg 프론트엔드가 아니라, 빠르고 안정적이며 UI가 현대적인 독립 데스크톱 미디어 플레이어가 되도록 구현한다.

특히 성능을 위해 기능을 무리하게 한 파일에 합치지 말고 플레이어 상태, FFmpeg 디코딩, GPU 렌더링, 오디오, 자막, UI, 단축키, 설정 및 다국어 시스템을 명확하게 분리한다.
